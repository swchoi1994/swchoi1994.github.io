Out of the box, Claude Code can read your files and run commands. Two additions make it far more useful: MCP servers, which connect it to outside tools such as an issue tracker or a database, and plugins, which package ready-made skills and commands. Both are managed from the terminal with a handful of commands. This guide walks through them on macOS and Windows, using output from real runs.

1. Plugin or MCP server: which is which

MCP serverPlugin
What it isOne connection to one tool or serviceA bundle: skills, agents, hooks, and sometimes MCP servers
Where it comes fromThe service itself, or a program you runA marketplace, which is a catalog of plugins
Shell commandclaude mcp ...claude plugin ...
Inside a session/mcp/plugin

The commands come in two forms. Those starting with claude are typed in your normal shell. Those starting with / are typed inside a running Claude Code session.

3. Add a remote MCP server

Most services offer a hosted server reached over HTTP. One command registers it. This one is the documentation's own example:

claude mcp add --transport http notion https://mcp.notion.com/mcp

The pattern is always claude mcp add --transport http <name> <url>. The name is yours to choose; it is how you refer to the server later.

Registering is not signing in. Start a session with claude, type /mcp, select the server and complete the sign-in in your browser. Servers that need attention are flagged in that panel.

For a service that uses a fixed key instead of a browser sign-in, pass it as a header:

claude mcp add --transport http my-api https://api.example.com/mcp --header "Authorization: Bearer YOUR_TOKEN"
One lineKeep these commands on a single line. Line-continuation characters differ between shells: a backslash in macOS and Linux shells, a backtick in PowerShell. A one-line command works in all of them.

4. Add a local MCP server, with a practice server

A local server is a program on your own machine that Claude Code starts and talks to. Use it for tools that need direct access to your files or your network. The command has one new element, a double dash:

claude mcp add --transport stdio <name> -- <command to start the server>

Everything before -- is an option for Claude Code. Everything after it is the server's own command, passed through untouched. Without the double dash, Claude Code would try to read the server's flags as its own.

To see the whole loop without installing anything, save this small server as hello_mcp.py. It offers one tool that returns a greeting:

"""A tiny MCP server with one tool, for testing that Claude Code can connect."""
import json
import sys


def send(message):
    sys.stdout.write(json.dumps(message) + "\n")
    sys.stdout.flush()


for line in sys.stdin:
    if not line.strip():
        continue
    request = json.loads(line)
    ident, method = request.get("id"), request.get("method")
    if method == "initialize":
        send({"jsonrpc": "2.0", "id": ident, "result": {
            "protocolVersion": request["params"]["protocolVersion"],
            "capabilities": {"tools": {}},
            "serverInfo": {"name": "hello", "version": "0.1.0"}}})
    elif method == "tools/list":
        send({"jsonrpc": "2.0", "id": ident, "result": {"tools": [{
            "name": "say_hello",
            "description": "Return a greeting for a name",
            "inputSchema": {"type": "object", "properties": {"name": {"type": "string"}}, "required": ["name"]}}]}})
    elif method == "tools/call":
        name = request["params"]["arguments"].get("name", "world")
        send({"jsonrpc": "2.0", "id": ident, "result": {"content": [{"type": "text", "text": f"Hello, {name}!"}]}})
    elif ident is not None:
        send({"jsonrpc": "2.0", "id": ident, "result": {}})

Add it, using the full path to the file. On Windows the command is usually python, not python3.

"Connected" means Claude Code started the program and completed the handshake. In a session, you can now ask it to use the hello tool to greet someone, and it will ask your permission before the first call.

Real local servers are usually started with a package runner. The documentation's example passes a key through the environment:

claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable -- npx -y airtable-mcp-server

Put --transport stdio between --env and the name, as shown. The documentation notes that a name placed directly after --env is read as another variable and rejected.

Notice "Pending approval". A file in a repository cannot switch on its own servers. Each person is asked to approve a project's servers the first time they start a session there. That protects you when you clone someone else's repository.

Do not commit secrets.mcp.json is meant to be committed, so keep keys out of it. Write ${API_KEY} in the file and let each person set the variable on their own machine. ${API_KEY:-fallback} supplies a default.

6. Manage your servers

TaskCommand
List servers with their statusclaude mcp list
Show one server's detailsclaude mcp get <name>
Remove a serverclaude mcp remove <name>
Sign in, reconnect or disable, inside a session/mcp
Add from a JSON snippet in a server's READMEclaude mcp add-json <name> '<json>'
Copy servers from the Claude desktop appclaude mcp add-from-claude-desktop, on macOS and WSL only
Forget approvals for project serversclaude mcp reset-project-choices

Many servers publish their setup as a JSON block. add-json accepts it directly. A remote entry needs a type; the documentation warns that an entry with a url and no type is treated as an error and skipped.

Quoting JSON on a command line differs between shells. If add-json gives you trouble in PowerShell, use the ordinary claude mcp add flags, or put the block in .mcp.json with a text editor.

7. Install a plugin

Plugins come from marketplaces. Anthropic's official one is named claude-plugins-official. Inside a session:

/plugin install commit-commands@claude-plugins-official

That is the documentation's example, a plugin that adds commands for committing and opening pull requests. In a session the command does not install at once. It opens the plugin's details so you can review them and pick a scope. To browse instead, type /plugin alone and use the Discover tab.

ScopeWho gets itRecorded in
UserYou, in every project on this machine~/.claude/settings.json
ProjectEveryone who works in the repository.claude/settings.json, which you commit
LocalYou, in this repository only.claude/settings.local.json

After installing, read the last line of the summary. "Plugin is now active" means it is ready. "Run /reload-plugins to apply" means one more step. Then type / and look for the plugin's skills, named in the form /commit-commands:commit.

The same install works from the shell, which is useful in a setup script:

claude plugin install commit-commands@claude-plugins-official

From the shell the default scope is user; add --scope project or --scope local to change it. On a brand-new machine where no session has been opened yet, the documentation says to register the marketplace first with claude plugin marketplace add anthropics/claude-plugins-official.

Read before you installA plugin can run hooks and start MCP servers on your machine. Install from publishers you trust, and look at what a plugin contains first; step 9 shows the command.

9. Practice the whole plugin loop offline

You can try every plugin command without touching the network, using a marketplace in a folder. It needs three small files:

my-marketplace/
  .claude-plugin/marketplace.json
  plugins/hello-plugin/
    .claude-plugin/plugin.json
    skills/hello/SKILL.md

marketplace.json lists the plugins:

{
  "name": "my-marketplace",
  "owner": { "name": "Your Name" },
  "plugins": [
    {
      "name": "hello-plugin",
      "source": "./plugins/hello-plugin",
      "description": "A greeting skill for testing plugin installation"
    }
  ]
}

plugin.json describes the plugin:

{
  "name": "hello-plugin",
  "description": "A greeting skill for testing plugin installation",
  "version": "0.1.0"
}

And SKILL.md is the skill itself:

---
name: hello
description: Greet the user by name. Use when the user asks for a greeting.
---

Reply with one friendly sentence that greets the user by the name they gave.

10. Update, disable and remove

TaskCommand
List installed pluginsclaude plugin list
Turn one off without removing itclaude plugin disable <plugin>@<marketplace>
Turn it back onclaude plugin enable <plugin>@<marketplace>
Update one plugin nowclaude plugin update <plugin>@<marketplace>
Remove itclaude plugin uninstall <plugin>@<marketplace>
List, refresh or remove marketplacesclaude plugin marketplace list, update <name>, remove <name>

Plugins from the official marketplace update automatically. For other marketplaces auto-update is off by default, and you can turn it on from the Marketplaces tab of /plugin. A running session keeps the versions it loaded; /reload-plugins applies an update without restarting.

In the practice run, disable, enable and uninstall each answered with one line, such as ✔ Successfully uninstalled plugin: hello-plugin (scope: user).

12. What you can do now

  • Tell a plugin from an MCP server and know which command family manages each.
  • Add a remote server, sign in through /mcp, and add a local server with the double dash in the right place.
  • Pick local, project or user scope on purpose, and keep secrets out of .mcp.json.
  • Install, inspect, update and remove plugins, and add a marketplace from GitHub or a folder.

Every server and plugin adds tool descriptions that the model reads on each request, so install what you use and remove what you do not. For the project files that sit beside these, see Claude Code project setup.
