The saved run ends with the same answer on x86-64, Arm and RISC-V: 120.0. The interesting difference appears below that answer, in the instructions GCC emitted for dot(). The function-size labels are 64, 52 and 38 bytes respectively. There is no stopwatch in this experiment.

This is part one of a processor series built around a small piece of code rather than a shopping comparison. All numbers below come from the supplied experiment files. Expand an architecture to inspect its output, or open the complete original record near the end.

Eight pairs of numbers

The C program supplies the arrays {1, 2, 3, 4, 5, 6, 7, 8} and {8, 7, 6, 5, 4, 3, 2, 1}. Its loop multiplies each pair and accumulates a floating-point sum. Here is the source exactly as supplied:

/* dot.c: the dot product, the small loop at the centre of most AI arithmetic. */
#include <stdio.h>

float dot(const float *a, const float *b, int n) {
    float sum = 0.0f;
    for (int i = 0; i < n; i++)
        sum += a[i] * b[i];
    return sum;
}

int main(void) {
    float a[8] = {1, 2, 3, 4, 5, 6, 7, 8};
    float b[8] = {8, 7, 6, 5, 4, 3, 2, 1};
    printf("%.1f\n", dot(a, b, 8));
    return 0;
}

The build script compiles this source for each target. The baseline uses -O2 -static. It runs the x86 binary directly and the other binaries through qemu-aarch64 and qemu-riscv64. The saved tool headers identify GCC 13.3.0 and QEMU AArch64 8.2.2.

Counting the loop bodies shown gives six instructions for each target. That count is a description of this compilation, not a measure of elapsed work or a ranking of processors. Nor does the smallest function here establish which architecture produces the smallest applications.

The vector build changes more than the target

The second group switches to -O3 -ffast-math and adds target-specific options. The saved x86 AVX2 excerpt uses ymm registers, with eight numbers at a time; Arm NEON uses v0.4s, with four. The Arm SVE excerpt instead contains whilelo predicates and predicated loads. The supplied notes leave SVE's width to the processor rather than assigning it a fixed lane count.

These are different compilation settings, not a controlled timing comparison. In particular, do not assume this one input proves identical floating-point behaviour for every possible input under the changed flags.

The RISC-V result is an observation about this build

With GCC 13.3 and -march=rv64gcv, the supplied record reports no vector instructions for this target. It still prints 120.0. Nothing here establishes what another compiler version would emit.
