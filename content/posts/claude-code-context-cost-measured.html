Before Claude Code reads your question, it has already written a long message of its own: its instructions, the definition of every tool, your project notes, the names of your skills. That message goes out with every request, and everything you add to your setup makes it longer. We wanted to know by how much, so we pointed Claude Code at a small recorder on our own machine and measured what arrived.

The short version: one thing you write costs its full size every single time, most things cost almost nothing, and one setting can double the bill.

As a rough guide, four characters make one token, so the baseline is on the order of 11,000 tokens and the largest row about 26,000. Those token figures are estimates; the byte counts are exact.

What is in the baseline

Three things stand out.

  • The tools are the bulk of it. Twelve tool definitions take 30,136 bytes, about 2,500 each. A tool definition is a small manual: what the tool does, when to use it, what each argument means.
  • "Say hello" was 9 bytes of a 10,081-byte message. The rest of the messages part is context Claude Code attaches for you: the date, the folder, what is available. This is also where your own additions land.
  • It is the same every time. We ran the baseline twice and got 46,254 bytes both times. That sameness is what makes caching work: an identical beginning can be reused instead of read again.

CLAUDE.md is the one that costs its full size

A 2,480-byte CLAUDE.md made the request 3,000 bytes larger. A 25,054-byte one made it 25,934 bytes larger. The whole file goes in, plus a few hundred bytes of wrapping, on every request of every session in that project.

Compare that with a skill. Each of our test skills was 2,688 bytes on disk, and ten of them added 1,844 bytes in total, about 184 each. Only a skill's name and description are sent; the body is read when the skill is used.

The rule this suggestsKeep in CLAUDE.md only what Claude needs on every task: the commands, the rules with no exceptions, where things are. Move anything that matters only sometimes, such as a release procedure or a style guide for one kind of file, into a skill. In our test that turned 2,688 bytes per request into 184.

How to write the short version is in setting up a project for Claude Code.

MCP servers: 1 KB or 56 KB, depending on one setting

We wrote a made-up server offering 40 tools, with realistic descriptions: 29 KB of definitions in all. Added to the project with default settings, it made each request +1,344 bytes larger. That is about 33 bytes per tool, because only the tool names are sent. This is the feature the documentation calls tool search: definitions are deferred, and Claude looks one up when it needs it.

Then we set ENABLE_TOOL_SEARCH=false, which the documentation describes as "all MCP tools loaded upfront, no deferral".

Tools in the requestRequest size
Default, with the 40-tool server1247,598
Tool search off, no MCP server2173,687
Tool search off, with the 40-tool server61101,938

Two costs appeared, and only one of them was expected.

  • The 40 tools now cost their full size: 28,251 bytes, about 700 each.
  • Eleven tools of Claude Code's own came along too. With tool search off and no MCP server at all, the request grew by 27,433 bytes, because built-in tools that are normally looked up on demand, among them web fetch, web search and the notebook editor, were all loaded at the start.

One more result surprised us. ENABLE_TOOL_SEARCH=auto sounds like the safe choice. It is a threshold mode: by the documentation, tools load upfront while their definitions total under 10 percent of the context window. Our 40 tools were under that line, so auto gave the largest request of the whole test, 103,647 bytes.

If you set this variable once and forgot whyCheck your shell profile and the env section of ~/.claude/settings.json for ENABLE_TOOL_SEARCH. Unset, every MCP tool is deferred. There are good reasons to load a few tools upfront, and the documentation shows how to do it per server or per tool, which is cheaper than switching deferral off for everything.

If you are writing a server yourself, the MCP server guide shows where the names and descriptions measured here come from.

Going the other way: small requests for scripts and small models

Two flags shrink the request sharply.

FlagRequest sizeWhat you give up
--tools "Read,Edit,Bash"14,840 bytesEvery built-in tool except the ones you name
--bare4,318 bytesAlmost everything automatic. The help text calls it a minimal mode that skips hooks, plugin sync, auto-memory and the automatic discovery of CLAUDE.md, among other things. You pass in what you want explicitly

This matters in two places. In a script or a CI job that runs Claude Code hundreds of times, a request a third the size is a third of the input to pay for and to wait for. And if you are running Claude Code against your own model, a model with a 32,000-token window cannot spare 11,000 of them for the opening message; naming three tools brings that down to roughly 3,700 by the same estimate.

Measure your own setup

The recorder is a small web server that pretends to be the model. It prints one line per request with the sizes of the three parts, then answers with a fixed sentence. Save it as recorder.py:

"""recorder.py: stand in for a model server and measure what each request from Claude Code is made of.

For every request it prints one line of JSON: the size in bytes of the whole request and of its three
parts (system instructions, tool definitions, messages), and the names of the tools. It then streams
back one fixed sentence. It is not a model.
"""
import json
from http.server import BaseHTTPRequestHandler, HTTPServer

REPLY = "Hello from the recorder."
size = lambda value: len(json.dumps(value, ensure_ascii=False).encode())


class Recorder(BaseHTTPRequestHandler):
    def do_POST(self):
        raw = self.rfile.read(int(self.headers.get("Content-Length", 0)))
        body = json.loads(raw or b"{}")
        tools = body.get("tools", [])
        print(json.dumps({"path": self.path.split("?")[0], "bytes": len(raw), "system": size(body.get("system", "")),
                          "tools": size(tools), "messages": size(body.get("messages", [])), "tool_count": len(tools),
                          "deferred": sum(1 for tool in tools if tool.get("defer_loading")),
                          "names": [tool.get("name") or tool.get("type") for tool in tools],
                          "beta": self.headers.get("anthropic-beta", "")}), flush=True)
        if not body.get("stream"):
            payload = json.dumps({"id": "msg_1", "type": "message", "role": "assistant", "model": body.get("model"),
                                  "content": [{"type": "text", "text": REPLY}], "stop_reason": "end_turn", "stop_sequence": None,
                                  "usage": {"input_tokens": 10, "output_tokens": 6}, "input_tokens": 10}).encode()
            self.send_response(200)
            self.send_header("Content-Type", "application/json")
            self.send_header("Content-Length", str(len(payload)))
            self.end_headers()
            self.wfile.write(payload)
            return
        self.send_response(200)
        self.send_header("Content-Type", "text/event-stream")
        self.end_headers()
        events = [
            ("message_start", {"type": "message_start", "message": {"id": "msg_1", "type": "message", "role": "assistant", "model": body.get("model"), "content": [], "stop_reason": None, "stop_sequence": None, "usage": {"input_tokens": 10, "output_tokens": 0}}}),
            ("content_block_start", {"type": "content_block_start", "index": 0, "content_block": {"type": "text", "text": ""}}),
            ("content_block_delta", {"type": "content_block_delta", "index": 0, "delta": {"type": "text_delta", "text": REPLY}}),
            ("content_block_stop", {"type": "content_block_stop", "index": 0}),
            ("message_delta", {"type": "message_delta", "delta": {"stop_reason": "end_turn", "stop_sequence": None}, "usage": {"output_tokens": 6}}),
            ("message_stop", {"type": "message_stop"}),
        ]
        for name, data in events:
            self.wfile.write(f"event: {name}\ndata: {json.dumps(data)}\n\n".encode())
        self.wfile.flush()

    def log_message(self, *args):
        pass


HTTPServer(("127.0.0.1", 8000), Recorder).serve_forever()

Run it in one terminal with python3 recorder.py. In another, go to the project you want to measure and send one question through it:

ANTHROPIC_BASE_URL=http://127.0.0.1:8000 ANTHROPIC_API_KEY=dummy ANTHROPIC_AUTH_TOKEN=dummy \
ANTHROPIC_DEFAULT_OPUS_MODEL=my-model ANTHROPIC_DEFAULT_SONNET_MODEL=my-model ANTHROPIC_DEFAULT_HAIKU_MODEL=my-model \
claude -p "Say hello"

Nothing leaves your machine during this, and no key is used: the settings send the request to the recorder instead of to Anthropic. Close the second terminal afterwards, or the settings stay in force for that shell. On Windows, set the six variables with $env:NAME = "value" first, as shown in the vLLM guide.

What this measurement does not show

  • Tokens. We counted bytes. The real token count depends on the model's tokenizer.
  • Money. On Anthropic's API a repeated beginning is served from a cache at a fraction of the normal price, so a large stable opening is cheaper than its size suggests. It still occupies the context window in full.
  • An interactive session. We used print mode. A normal session carries more, and grows with every turn.
  • Your version. These are Claude Code 2.1.322's numbers. The tool list changes between releases, which is one more reason to run the recorder yourself.
