애플 앱 심사 가이드라인 개정, 개발자가 제출 전에 확인할 것

Seongwoo Choi · 2026.10.17 · 3분 읽기

Apple이 Oct 16th 2026에 App Review Guidelines(앱 심사 가이드라인)를 개정했습니다. 이번 개정은 AI로 만든 비동의 성적 이미지 관리, 심사 뒤에 기능을 여는 행위, 아동 착취와 인신매매 관련 앱 차단을 더 분명하게 적었습니다. App Store에 앱을 올리는 개발자라면 제출 전에 기능 목록과 콘텐츠 정책을 다시 점검할 필요가 있습니다.

1. 바뀐 조항

가장 큰 변화는 1.2 조항입니다. 콘텐츠 관리 요건에 AI 도구로 만든 비동의 성적 이미지(nonconsensual intimate imagery)가 명시적으로 들어갔습니다. 사용자 생성 콘텐츠를 다루는 앱은 이런 이미지를 사전에 막고 제거해야 합니다. 안전장치를 갖추지 않았거나 통보를 받고도 고치지 않으면 Developer Code of Conduct 위반으로 App Store에서 제거될 수 있다고 Apple은 설명했습니다.

2.5.19 조항은 심사 때 보여준 기능과 승인 뒤의 실제 기능이 다른 행위를 금지합니다. 영어로는 bait-and-switch라고 부르는 방식입니다. 기존 2.3.1에 있던 내용을 새 조항으로 분리했습니다. 이 규칙을 어기면 App Store에서 제거되고 Apple Developer Program에서도 내보내질 수 있습니다.

조항 5는 인신매매나 아동 착취를 돕는 앱을 App Store에서 제거하고, 다른 경로로 배포되는 것도 막겠다고 명시했습니다. 2.3.14는 창작물 자산(creative assets)에 관한 새 조항입니다. 세부 문구는 공식 원문에서 직접 확인해야 합니다.

2. 개발자가 바로 확인할 것

① 심사 메모와 출시 기능이 같은지 봅니다. 원격 설정(remote config)이나 기능 플래그로 나중에 여는 기능이 있다면 심사 메모에 용도를 정확히 적어야 합니다. 2.5.19 기준으로는 숨은 기능처럼 보이는 것 자체가 위험입니다.

② AI 이미지 생성, 편집, 공유 기능이 있다면 실제 인물을 성적으로 만드는 요청을 막는 필터가 작동하는지 시험합니다. Apple 문구는 '사후 대응'이 아니라 사전에 막고 제거해야 한다는 표현입니다.

③ 사용자 생성 콘텐츠 기능이 있는 앱은 불쾌한 콘텐츠 필터, 신고 경로, 계정 차단 기능을 모두 갖춰야 합니다. 이 요건은 개정 전에도 있었지만, 이제 어떤 기능이 문제 되는지 조항 문구로 더 분명해졌습니다.

3. 아직 확인되지 않은 것

Apple은 번역본을 한 달 안에 제공한다고 밝혔습니다. 2.3.14의 적용 범위와 1.2 조항의 '적절한 안전장치'가 구체적으로 무엇인지는 공개 문서만으로는 판단하기 어렵습니다. Apple은 지난해 안전 문제가 있는 앱 15만 개 이상의 출시를 막았고 19만 3천 개 이상의 개발자 계정을 해지했다고 밝혔습니다. 이 수치는 회사 발표이며 독립적으로 확인하지 못했습니다.

4. 실무 한 줄 정리

이미 승인된 앱이라도 이번 개정 뒤에는 '승인 뒤에 기능이 바뀌지 않는가'를 먼저 점검하는 편이 안전합니다. 기능 목록, 심사 메모, 콘텐츠 필터, 신고 기능을 한 번에 맞춰 두면 재심사 위험을 줄일 수 있습니다.
