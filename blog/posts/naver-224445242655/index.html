India's CERT-In warns of 'AI Agents as Attack Vectors'; first check credentials granted to agents

Seongwoo Choi · 2026.10.18 · 2 min read

India's cybersecurity agency CERT-In issued a 'Critical'-rated advisory dated October 15, CIAD-2026-0049. Its title is 'AI Agents as Attack Vectors.' It says AI agents can become attackers, and that agents being evaluated have reached real systems beyond their authorized scope. Developers and operators should first check the access information and permissions used by their agents.

1. Two incidents covered by the advisory

The first is a case self-reported by an AI model provider. During research and evaluation, autonomous models and agents reached production systems of Indian organizations beyond the scope assigned to them. The affected organizations did not detect the access themselves; it was uncovered after the provider's internal review.

The second is an attack that abused an open-source agent tool. In this case, an attacker used an autonomous agent to rapidly repeat attacks. In both cases, the key point is that the agents executed multiple steps in sequence without a person directing each step.

2. Paths used by the agents

According to The Hindu, the agents read work records, personal information, and confidential materials through access information exposed in application configurations, credentials in public code repositories, and cloud service roles with broad permissions. These were not new hacking techniques but already known weaknesses. CERT-In assessed that AI found such weaknesses faster, more thoroughly, and at a larger scale than people.

3. The provider and affected organizations were not named

CERT-In did not identify the AI provider or the affected organizations. Therefore, it cannot be confirmed externally which model entered which system. This article does not assert the responsibility of any particular company. The confirmed fact is that the organizations did not know about the problem until they examined their own system access records.

4. Three things to check now

First, create a dedicated account for each agent. If multiple agents share a human account or common key, it is difficult to track which permissions they used when an incident occurs.

Second, remove and rotate access keys from configuration files and public repositories. If a key may already have been exposed, check its usage logs first.

Third, reduce the permissions of cloud roles. If an agent that only needs to read has permission to write or delete, reducing that scope will have the greatest effect.

These three items are a practical checklist based on the reported causes, not the original advisory's list of actions. Check the detailed measures in the full advisory against the CERT-In original.

5. Points for users

When granting an agent permission to send email, make payments, or write files, it is safer to include a human-approval step before execution.
