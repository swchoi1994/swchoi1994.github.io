What to do when Windows fails to extract a ZIP: distinguishing password-protected files from long-path errors

Seongwoo Choi · 2026.11.09 · 2 min read

When an archive shows an error or will not open, first determine whether it is password-protected, has an excessively long path, or was corrupted during download; this article gives a Microsoft-based checklist.

  • 2. Check whether it is a long-path error

When an archive shows an error or its contents do not open even when you double-click it, first identify the cause. The solution differs depending on whether the archive is password-protected, the file path is too long, or the file was corrupted during download. Based on official Microsoft documentation, this article explains how to distinguish the three causes and the order in which to check them.

1. First check the archive format and whether it has a password

Microsoft Support explains that Windows 11 24H2 supports the ZIP, RAR, 7z, and TAR formats. The same document states that operations on encrypted archives are not supported and advises using a non-Microsoft application such as 7-Zip or WinRAR for password-protected archives. Therefore, if the archive asks for a password when you open it or the built-in extractor keeps failing, first ask the person who provided the file whether it is password-protected.

2. Check whether it is a long-path error

The default path-length limit for the Windows API is MAX_PATH, or 260 characters. Microsoft Learn explains that although this limit was removed for many functions starting with Windows 10 version 1607, apps must explicitly opt in to the new behavior. It also states that the shell user interface may not correctly interpret long paths. If the combined path of the folders inside the archive and the save location is long, move the archive to the desktop or a short folder and try extracting it again. This article does not recommend changing the registry.

3. Check whether the file is corrupted

If the connection was interrupted during download or the file was truncated while being sent through a messenger, extraction itself may fail. The most reliable solution is to download the file again from the original provider. If the same error occurs after downloading the same file again, suspect the original file. If the provider has published a hash value such as SHA-256, compare it with the file's hash value.

4. Checklist

1) Check whether the file extension is .zip, .rar, .7z, or .tar. 2) If it asks for a password or will not open, ask the provider whether it is password-protected, and use a tool such as 7-Zip for password-protected archives. 3) If the error appears to involve a long path, move the archive to a short folder and extract it again. 4) If the same error occurs after downloading it again, obtain a new file from the original provider.

5. What to check after extraction

Check whether the number of extracted files matches the archive's file list. If you are unsure of a file name's actual extension, also see How to turn on the display of Windows file extensions and distinguish files with double extensions ↗. It is safer not to delete the original archive until you have finished checking everything after extraction.
