What to check before scanning Windows disk errors: divide chkdsk options into status checks, repairs, and physical scans

Seongwoo Choi · 2026.11.06 · 3 min read

When a disk error is suspected, chkdsk options should be chosen by purpose: check the status first, repair file-system errors with /f, and consider /r only when physical-sector damage is suspected.

When a disk error is suspected, many people immediately run chkdsk with /f or /r. However, depending on the option, chkdsk may only display the status, repair file-system errors, or read physical sectors and attempt recovery. Based on Microsoft’s official documentation, this article organizes the options by role and outlines a sequence for deciding whether to check first and repair afterward.

1. Running it without arguments does not repair anything

Open Command Prompt with administrator privileges and enter only a drive letter, such as chkdsk D:, to display the volume’s status. Microsoft’s documentation explains that running it without parameters does not repair errors. Therefore, this status check is sufficient as the first step. However, the documentation also notes that running it without /f on a partition in use may report errors that do not reflect the actual condition because the drive cannot be locked.

2. Choose options based on the scope of the repair

① /scan: Runs an online scan on an NTFS volume. Use this option when you want to check the file-system structure without fully locking the drive.

② /f: Repairs logical disk errors. The drive must be lockable, and any open files should be closed before running it. If the drive cannot be locked, a message asks whether to schedule the check for the next restart.

③ /r: Locates bad physical sectors and attempts to recover readable information. Because /r includes the functionality of /f, it may take much longer. The documentation explains that it can take especially long on large HDDs because every sector is read.

3. Example: when a folder on an external drive will not open

This is a hypothetical example. Suppose a particular folder on external drive E: will not open and displays a corruption-related error. The sequence is as follows. First, confirm that important files are backed up elsewhere. Second, check only the status by running chkdsk E: in an administrator Command Prompt. Third, if there are errors, close all open files and run chkdsk E: /f. Fourth, consider /r only if the same symptoms remain or physical damage is suspected. In this example, the actual scan results depend on the condition of the drive.

4. Decide what to do next using the exit code

An exit code appears when the scan finishes. 0 means that no errors were found. 1 means that errors were found and repaired. 2 means that only cleanup was performed, or that errors were not repaired because /f was not specified. 3 means that the scan could not be performed, errors could not be repaired, or errors were not repaired because /f was not specified. If the result is 2 or 3, first check whether you omitted /f. You can check the code in the same window with echo %errorlevel%.

5. Points to check before running it

First, avoid interrupting it midway if possible. Microsoft’s documentation does not recommend interruption, but it also explains that interrupting it will not leave the volume in a worse state than before and that running it again can identify the remaining problems. Second, organize open files and confirm the backup status beforehand. Third, avoid frequently repeating a full /r scan on an SSD. The documentation states that the effect of an occasional scan is not significant, but repeated scans may increase the number of writes and erases.

6. Summary: check the status → confirm the backup → /f → /r only when necessary

Disk scans should begin with checking, before making repairs. Check the status, back up important files, and use only the options you need.
