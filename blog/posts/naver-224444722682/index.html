Perplexity SPACE 오픈소스 공개, 에이전트 샌드박스에서 확인할 세 가지 경계

Seongwoo Choi · 2026.10.17 · 2분 읽기

Perplexity가 2026년 10월 15일 자사 에이전트 샌드박스 플랫폼 SPACE(Sandboxed Platform for Agentic Code Execution)를 Apache 2.0 라이선스로 공개했습니다. 회사에 따르면 SPACE는 7월부터 Perplexity Computer의 작업을 실행해 온 내부 시스템입니다. 작업마다 별도의 Firecracker microVM을 띄우고, 네트워크 접근과 인증 정보는 샌드박스 바깥에서 관리합니다.

1. 샌드박스마다 자체 운영체제를 둔다

각 SPACE 샌드박스는 자체 운영체제를 가진 작은 가상머신입니다. 에이전트가 명령을 실행하고 패키지를 설치하더라도 호스트 시스템과 경계가 생깁니다. 샌드박스의 생성, 일시정지, 재개, 삭제는 중앙 제어 계층이 맡습니다.

Perplexity는 모델 안전장치만으로는 부족하다고 봅니다. 시스템 바깥에도 독립된 통제를 두어, 안전장치가 실패해도 피해 범위를 제한하겠다는 설계입니다.

2. 인증 정보는 샌드박스 밖에 둔다

회사는 샌드박스를 신뢰하지 않는 공간으로 취급한다고 설명합니다. 에이전트는 허가된 서비스에 접근할 수 있지만, 인증 정보가 작업 환경 안에 저장되지 않습니다. 에이전트를 직접 만드는 개발자라면 인증 정보가 어디에 놓이는지부터 확인해야 합니다.

스냅샷과 일시정지 기능도 같이 볼 필요가 있습니다. 실행 중인 환경을 저장해 두었다가 복구하거나 분기할 수 있어, 장시간 돌아가는 에이전트 작업에 쓰기 편합니다.

3. 공개된 보안 숫자는 두 가지로 나눠 읽을 것

Perplexity는 공개 보안 평가에서 에이전트가 가상머신을 벗어나 호스트에 닿으려는 108회 시도 중 성공 사례가 없었다고 밝혔습니다. 같은 평가에서 일부 시도는 네트워크 제한을 우회했고, 회사는 이를 고쳤다고 설명합니다.

그래서 탈출 0건은 가상머신 경계에 대한 결과이고, 네트워크 정책은 실제로 뚫린 사례가 있었다는 뜻입니다. 회사 측 성능 비교인 샌드박스 생성 속도 3~5배 향상도 독립 측정이 아니므로 참고 수치로만 보는 것이 맞습니다.

4. 도입 전에 확인할 체크리스트

① 네트워크 송신 정책과 인증 정보가 샌드박스 바깥에서 관리되는지 확인합니다.

② 일시정지, 스냅샷, 분기 기능이 내 작업 흐름에 실제로 필요한지 따집니다.

③ 보안 평가에서 어떤 공격 조건을 시험했는지 원문에서 확인합니다. 시험 범위 밖의 위협은 별도로 막아야 합니다.
