EmbeddingGemma 2 공개, 검색 인덱스 차원을 768에서 줄일지부터 계산할 것

Seongwoo Choi · 2026.10.19 · 3분 읽기

구글 딥마인드가 2026년 10월 6일 임베딩 모델 EmbeddingGemma 2를 공개했습니다. Gemma 4를 바탕으로 만든 오픈 웨이트(open-weight) 모델이고 라이선스는 Apache 2.0입니다. 텍스트, 코드, 이미지, 영상, 오디오를 하나의 768차원 벡터 공간에 넣기 때문에 같은 검색 인덱스에서 여러 형식을 함께 찾을 수 있습니다. 검색 기능을 만드는 개발자라면 먼저 두 가지를 정해야 비용이 계산됩니다. 어떤 인코더를 올릴지, 그리고 벡터를 몇 차원으로 저장할지입니다.

1. 인코더는 필요한 것만 올리십시오

모델은 모달리티별 인코더를 따로 로드할 수 있습니다. 텍스트와 코드만 쓰면 270M 파라미터로 충분하고, 이미지를 더하면 440M, 오디오를 더하면 570M, 전부 쓰면 740M입니다. 공식 개발자 가이드에 따르면 나중에 인코더를 추가해도 이미 계산해 둔 임베딩은 다시 만들 필요가 없습니다. 구글은 Pixel 11 Pro 기준으로 텍스트 전용 가중치가 활성 메모리 약 191MB, 전체 멀티모달 모델이 약 567MB를 쓴다고 밝혔습니다. 이 수치는 회사 측 측정값입니다.

2. 벡터 차원은 저장비용과 품질을 함께 보십시오

가이드는 Matryoshka 방식으로 768차원을 512, 256, 128차원으로 줄이는 방법을 보여 줍니다. 100만 개 벡터를 bf16(벡터당 2바이트)으로 저장하면 768차원은 약 1.5GB, 128차원은 약 250MB입니다. 구글이 밝힌 품질 유지율은 다음과 같습니다. 256차원은 텍스트와 코드에서 원본 품질 대부분을 유지하고, 이미지·영상·음성 검색에서는 약 95%를 유지합니다. 128차원은 텍스트와 코드에서 약 90%, 멀티모달 검색에서는 약 75%입니다. 저장량은 256차원에서 3분의 1, 128차원에서 6분의 1로 줄어듭니다.

구글 가이드는 128차원을 텍스트 중심의 대형 인덱스나 1차 후보 추림(shortlisting)에 권하고, 멀티모달 질의에 쓰기 전에는 실제 데이터에서 먼저 검증하라고 설명합니다.

3. 질의와 문서는 같은 차원으로 임베딩하십시오

검색 질의에는 SearchQuery 프롬프트, 문서에는 Document 프롬프트를 붙이도록 가이드는 안내합니다. 자르는 차원(truncate_dim)도 질의와 문서가 같아야 합니다. 차원이 다른 벡터끼리는 비교할 수 없으므로 인덱스를 만든 뒤 차원을 바꾸면 검색이 깨집니다. 설치는 sentence-transformers 6.1.0 이상에서 pip install -U sentence-transformers[image,audio,video] transformers 명령으로 하고, 모델 ID는 google/embeddinggemma-2입니다.

4. 발표만으로 확인되지 않은 것

첫째, 품질 유지율과 메모리 수치는 구글의 자체 평가입니다. 우리가 따로 재현하지 않았습니다. 둘째, 제로샷 의도 분류(intent routing)는 시연으로 소개됐지만 정확도 수치는 확인하지 못했습니다. 셋째, 안드로이드용 ML Kit 서비스는 발표 시점에 몇 주 안에 나온다고만 했습니다. 지금 실제로 쓸 수 있는지는 확인하지 않았습니다.
