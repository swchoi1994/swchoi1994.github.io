Run a program at the same time every day with Windows Task Scheduler

Seongwoo Choi · 2026.10.31 · 3 min read

Windows Task Scheduler automatically runs programs or commands at specified times or under specified conditions. This article covers the simplest setup for running one program at the same time every day.

  • 1. Three things to decide before registering
  • 2. Create a task from Command Prompt
  • 3. Choose the execution permission options
  • 4. Four things to check after registration

Windows Task Scheduler is a built-in tool that automatically runs programs or commands at specified times or when specified conditions are met. This article covers the simplest setup for running one program at the same time every day. The command examples follow the syntax in Microsoft’s official documentation, but I did not run them on an actual PC or verify the results while writing this article.

1. Three things to decide before registering

First is the target to run. Copying the program’s full path from File Explorer helps reduce mistakes. Second is the frequency. Choose one of daily, weekly, or one-time. Third is the start time. Write the time in 24-hour format (HH:mm). For example, 9 a.m. is 09:00, and 9 p.m. is 21:00.

If the path is incorrect, the task may be created but fail to run. So check the path first before registering it. If the path contains spaces, enclose it in quotation marks.

2. Create a task from Command Prompt

The Microsoft Learn schtasks create documentation shows the format for specifying the frequency with /sc, the task name with /tn, the program to run with /tr, and the start time with /st. The following example opens Notepad every day at 09:00. Because Notepad is in a system folder, its path may be omitted, but for other programs it is safer to enter the full path.

schtasks /create /tn "Open Notepad daily" /tr notepad.exe /sc daily /st 09:00

If a task with the same name already exists, registration fails. /f suppresses warnings and overwrites the existing task, so add it only when it is acceptable to overwrite the task.

3. Choose the execution permission options

The /rl option sets the execution level. LIMITED runs with the lower permissions of a standard user, while HIGHEST runs with the highest permissions. For programs that do not strictly require administrator privileges, it is safer to use LIMITED or the default value. If an incorrect program is registered with elevated privileges, the potential scope of damage also increases.

The /it option restricts execution to when the account running the task is logged on. /np runs without storing a password; in this case, the resources that can be used are limited to local resources. If the task requires a network drive, review the conditions before using this option.

4. Four things to check after registration

Open the Task Scheduler Library in the Task Scheduler app and find the name you just created. Then check that it is set to every day at 09:00 in the Triggers tab and that the program path is correct in the Actions tab. In the General tab, check the account used to run it and the privilege level. In the Conditions and Settings tabs, check the laptop’s power conditions and how missed tasks are handled. Menu names may vary slightly depending on the Windows version.

After execution finishes, check the “Last Run Result” value. 0 only means that the program returned a success code; it does not guarantee that the intended output was created. For example, if it is a backup program, you must separately verify that the backup file was actually created.

5. Check power conditions on a laptop

If the PC is turned off or in sleep mode at the scheduled time, the task may not run at the expected time. Also check whether a condition prevents it from running while the laptop is using battery power. For important tasks, it can help to enable the option to handle a missed run when you turn on the PC after the scheduled time.

To delete the task, right-click it in Task Scheduler and choose Delete, or use the command schtasks /delete /tn "Open Notepad daily" /f. Before deleting it, check the name and path one more time to confirm which program the task runs.
